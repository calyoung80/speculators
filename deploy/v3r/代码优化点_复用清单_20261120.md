## A. 数据加载层（自研代码，可移植性最高）

### A1. `readonly_views.py` — PROT_READ 零拷贝视图加载

**病灶**：`safetensors.torch.load_file` 把每个 tensor **复制**进 worker 堆。states 样本 ~1GB/个 × 32 worker 并发 → 匿名内存 ~807G（11-19 22:36 事故实测项）。

**机制**：`mmap(PROT_READ)` + `np.frombuffer` + `torch.from_numpy` 返回**视图**——样本字节只存在一份，与 page cache 共享。

**四个必须保留的实现细节**（复用时最容易丢的）：
1. **只用 PROT_READ**：safetensors 默认私有可写映射会被 CoW 成永不释放的匿名页（sglang#37822 实测）；只读映射不可能。**代价：视图上 in-place 写 = SIGSEGV（不是异常）**——数据路径必须只读
2. **`_MMapHolder` + `weakref.finalize`**：tensor 属性锚定 holder → 全部 tensor 死亡时才关映射并触发 A2 的 fadvise（延迟释放，不抢热数据）
3. **BF16 特殊路径**：`np.uint16` 中转 + `.view(torch.bfloat16)`（numpy 无 bf16 原生）；exotic dtype → 返回 None 走回退
4. **永不 raise**：任何 parse/IO 错误返回 None，调用方回退 `load_file`

**门控**：`HS_READONLY_VIEWS=1`（默认关 = 逐字节旧行为）

### A2. `page_cache_drop.py` — POSIX_FADV_DONTNEED 页缓存释放

**病灶**：states 文件从 cephfs 读入后留在内核 page cache，**无驱逐策略**；ceph osd flap 时 file LRU 被钉死 → MemAvailable 秒级崩塌（#6/7/8/9/12 五次中断的贡献项）。

**机制**：加载后对整文件 `os.posix_fadvise(fd, 0, 0, POSIX_FADV_DONTNEED)`。每文件每 epoch 只读一次（间隔小时级）→ 丢弃零重读代价。

**细节**：`min_bytes=64MiB` 过滤小文件防 syscall 垃圾（`HS_FADVISE_MIN_BYTES` 可调）；best-effort 永不 raise；实测 cephfs 255/256MB=99.6% 释放。

**门控**：`HS_FADVISE_DONTNEED=1`

### A3. `transfer.py` 接线模式（10 行核心，复用时照抄）

```python
try:  # 1120 fix: page-cache drop + read-only views (opt-in env, default off)
    from hs_connectors.page_cache_drop import drop_page_cache
    from hs_connectors.readonly_views import load_file_views, views_enabled
except Exception:  # training must never die on this
    drop_page_cache = lambda *a, **k: False
    load_file_views = lambda *a, **k: None
    views_enabled = lambda: False

def _load_hs_file(file_path):
    ...
    if views_enabled():
        sample = load_file_views(file_path)
        if sample is not None:
            drop_page_cache(file_path)   # 延迟版：样本死后由 finalizer 触发
            return sample
    sample = load_file(file_path)         # 回退路径
    drop_page_cache(file_path)            # ★ 回退也释放页缓存——A2 可独立启用
    return sample
```

**设计三原则**（复用必守）：① env 门控默认关，部署≠激活；② 优化代码永不 raise/永不改训练数据语义；③ 任何失败静默回退旧路径。

## B. 分配器层（launch 脚本 env 栈）

```bash
export MALLOC_ARENA_MAX=2                    # 限 arena 数（防 per-thread arena 泛滥）
export NUMPY_MADVISE_HUGEPAGE=0              # numpy 不主动 madvise 大页
export MALLOC_CONF=thp:never                 # views 变体追加: dirty_decay_ms:0,muzzy_decay_ms:0
export MALLOC_TRIM_THRESHOLD_=134217728      # 128MiB：禁动态阈值棘轮
export MALLOC_MMAP_THRESHOLD_=134217728      # 128MiB：大块直接 mmap（可被 fadvise/归还）
export LD_PRELOAD=.../jemalloc/libjemalloc53.so.2
```

**说明**：jemalloc（B1）与 glibc 三参（B2）并存——jemalloc 吃掉主要分配，glibc 参数兜底非 jemalloc 路径。`dirty/muzzy_decay_ms:0` 是 views 变体新增：迫使 free 后的页立即归还内核（针对 collate 队列+分配器滞留，Anon 807G 重定性结论）。

## C. 内核/宿主层

```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled   # 双机
```

**教训（2026-11-20 11:50 实证）**：sysfs **不抗重启**——08:20 双机同步重启后回退 `[always]`，3.5h 内 khugepaged 重新聚合出 384G/546G AnonHugePages。**复用时必须持久化**（systemd unit 或 rc.local），否则每次重启都是裸奔窗口。

`PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`（C2）：NPU 显存分配器段扩展，减少碎片。
